# Canal WhatsApp — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O agente atende pelo WhatsApp (Cloud API da Meta) com o mesmo comportamento do Telegram. A equipe responde pela Inbox. O lembrete sai por template.

**Architecture:** O adaptador fica nas bordas. `core/integrations/whatsapp.py` fala com a Meta. `core/integrations/whatsapp_updates.py` converte o webhook para o formato de update que os handlers já leem. `core/channels.py` é o portão único de envio ao cliente e escolhe o canal pelo prefixo `wa:` do `chat_id`. A lógica de conversa não muda. Tudo o que é da equipe continua no Telegram.

**Tech Stack:** Python 3.12, FastAPI, httpx (teste com `httpx.MockTransport`), psycopg 3, pytest + pytest-asyncio (modo auto), ruff, pyright 1.1.411.

**Spec:** `docs/superpowers/specs/2026-10-05-whatsapp-design.md`

## Global Constraints

- Branch `feat/whatsapp`. Commits **sem** linha `Co-Authored-By` (regra do Paulo).
- Testes locais: `DB_HOST=172.21.0.3 .venv/bin/python -m pytest -p no:warnings`. Não exportar `AWS_*`/`RESTIC_*` no shell (quebra `test_backup.py`).
- Graph API: `https://graph.facebook.com/{WHATSAPP_GRAPH_VERSION}/…`, padrão `v23.0`, cabeçalho `Authorization: Bearer {WHATSAPP_ACCESS_TOKEN}`.
- Prefixos: `chat_id` do WhatsApp = `"wa:" + wa_id`; `file_id` de mídia = `"wa-media:" + media_id`; `update_id` = `"wa:" + message.id`.
- Limites da Meta: texto 4096; corpo de mensagem interativa 1024; até 3 botões de resposta com título até 20; lista até 10 linhas com título até 24; rótulo do botão da lista até 20.
- `settings.whatsapp_configured()` só é verdadeiro com `WHATSAPP_APP_SECRET`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_ACCESS_TOKEN` e `WHATSAPP_WEBHOOK_VERIFY_TOKEN`.
- Nunca imprimir credenciais em log ou teste. O log do token inválido cita o **nome** `WHATSAPP_ACCESS_TOKEN`, nunca o valor.
- Os 501 testes atuais continuam passando. Eles fazem stub de `telegram.send_message(chat_id, text, reply_markup=None, **kwargs)`, então o portão chama o Telegram **por atributo do módulo** e com `parse_mode`/`reply_markup` como keywords.

## Review Focus

1. **Lote:** um POST da Meta com várias mensagens (ou várias `entry`) vira vários updates, na ordem. Teste na Task 3.
2. **Outro número:** mensagem cujo `metadata.phone_number_id` não é o nosso é ignorada. Teste na Task 3.
3. **Só status:** webhook só com `statuses` (entregue, lido) devolve 200 e não enfileira nada. Testes nas Tasks 3 e 4.
4. **Número longo:** `wa_id` de 15 dígitos gera `chat_id` de 18 caracteres, que cabe no `VARCHAR(20)`. Teste na Task 3.
5. **Áudio grande:** acima de `max_voice_bytes` vira `None` e segue o caminho do "não consegui ler". Testes nas Tasks 1 e 5.
